# DIFAI-HUB — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construire un IDE/cockpit Electron qui lance des sessions Claude interactives et rend visibles, en live, les agents qu'elles dispatchent — avec corrélation déterministe, notifications d'état et fermeture propre.

**Architecture:** Le dé-risquage (Étape 0) valide d'abord la corrélation `tabId↔session` et le format/timing des transcripts d'agents sur Windows. Puis l'app Electron : un main process en 4 modules isolés (PtyManager, HookServer, SessionRegistry, TranscriptWatcher), un renderer UI (layout B), un preload IPC étroit. La corrélation repose sur une variable d'env `DIFAI_HUB_TAB` injectée au spawn et renvoyée par un hook `SessionStart` vers un mini-serveur HTTP local.

**Tech Stack:** Electron, xterm.js + node-pty, chokidar, serveur HTTP local (Node natif), Vitest. Node 18+ (fetch natif).

**Note de portée :** Ce document détaille **l'Étape 0 (POC)** entièrement. Les plans des sous-systèmes V1 (§ Roadmap) seront détaillés **après** le POC, car leur contenu (parser de transcript notamment) dépend du format exact que le POC révèle. Cet ordre est volontaire.

### Task 0.2 : Serveur HTTP de capture des hooks

**Files:**
- Create: `poc/server.mjs`

- [ ] **Step 1: Écrire `poc/server.mjs`**

```js
import { createServer } from 'node:http';
import { appendFileSync } from 'node:fs';

const PORT = 7711;

const server = createServer((req, res) => {
  if (req.method !== 'POST') { res.writeHead(404); res.end(); return; }
  let body = '';
  req.on('data', (c) => { body += c; });
  req.on('end', () => {
    console.log('[HOOK RECU]', body);
    appendFileSync('captured-hooks.jsonl', body + '\n');
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end('ok');
  });
});

server.listen(PORT, '127.0.0.1', () => {
  console.log(`POC server: http://127.0.0.1:${PORT}`);
});
```

### Task 0.3 : Hook SessionStart isolé dans le POC

- [ ] **Step 1: Écrire `poc/hooks/on-session-start.mjs`**

```js
// Hook SessionStart : lit l'evenement sur stdin, lit DIFAI_HUB_TAB dans l'env,
// POST la correlation au serveur local du POC.
import { readFileSync } from 'node:fs';

const input = JSON.parse(readFileSync(0, 'utf8')); // fd 0 = stdin
const payload = JSON.stringify({
  hook: 'SessionStart',
  tabId: process.env.DIFAI_HUB_TAB ?? null,
  session_id: input.session_id ?? null,
  transcript_path: input.transcript_path ?? null,
  cwd: input.cwd ?? null,
  source: input.source ?? null,
});

try {
  await fetch('http://127.0.0.1:7711', { method: 'POST', body: payload });
} catch (e) {
  // ne jamais bloquer la session si le hub est absent
  process.stderr.write(`[poc hook] POST echoue: ${e}\n`);
}
```

### Task 0.4 : Spawn de `claude` via node-pty avec injection d'env

**Files:**
- Create: `poc/spawn.mjs`

- [ ] **Step 1: Écrire `poc/spawn.mjs`**

```js
import pty from 'node-pty';

const TAB_ID = 'poc-tab-1';
const shell = process.platform === 'win32' ? 'claude.cmd' : 'claude';

const term = pty.spawn(shell, [], {
  name: 'xterm-color',
  cols: 110,
  rows: 32,
  cwd: process.cwd(),
  env: { ...process.env, DIFAI_HUB_TAB: TAB_ID },
});

term.onData((data) => process.stdout.write(data));
term.onExit(({ exitCode }) => {
  console.log(`\n[poc] claude exited (code ${exitCode})`);
  process.exit(exitCode);
});

process.stdin.setRawMode?.(true);
process.stdin.resume();
process.stdin.on('data', (d) => term.write(d.toString()));
```

### Task 0.6 : Observateur du répertoire de transcript (setup Q2)

**Files:**
- Create: `poc/watch-transcript.mjs`

- [ ] **Step 1: Écrire `poc/watch-transcript.mjs`**

```js
// Surveille un repertoire et logge tout fichier cree/modifie avec sa taille.
// Usage: node watch-transcript.mjs "<dossier du transcript_path recu>"
import chokidar from 'chokidar';
import { statSync } from 'node:fs';
import { basename } from 'node:path';

const dir = process.argv[2];
if (!dir) { console.error('Usage: node watch-transcript.mjs <dir>'); process.exit(1); }

const size = (f) => { try { return statSync(f).size; } catch { return '?'; } };

chokidar.watch(dir, { ignoreInitial: false, depth: 1 })
  .on('add', (f) => console.log(`[ADD]    ${basename(f)}  (${size(f)} o)`))
  .on('change', (f) => console.log(`[CHANGE] ${basename(f)}  (${size(f)} o)`));

console.log(`[poc] watch sur: ${dir}`);
```

## Roadmap des plans V1 (à détailler après le POC)

Chaque sous-système ci-dessous fera l'objet de son propre plan détaillé (tâches TDD bite-sized), rédigé une fois le POC livré et le format de transcript confirmé. Chacun produit un logiciel testable indépendamment.

1. **Plan V1-A — Squelette Electron + terminal embarqué.**
   App Electron (main/preload/renderer), `PtyManager`, un onglet, `xterm.js` relié à un `pty` `claude`. Livrable : un terminal claude interactif fonctionne dans une fenêtre Electron (node-pty rebuildé pour Electron). Tests : `PtyManager` (spawn/kill/relais I/O) sous Vitest.

2. **Plan V1-B — HookServer + SessionRegistry + corrélation.**
   Mini-serveur HTTP local (port dynamique + fichier de découverte), `SessionRegistry`, installation assistée des hooks (`SessionStart`, `Stop`, `Notification`, `SubagentStop`) avec **diff avant/après** dans `settings.json`. Livrable : un onglet se corrèle à sa session. Tests : routing HookServer, transitions du Registry, calcul des compteurs.

3. **Plan V1-C — TranscriptWatcher + rail d'agents + console split.**
   `TranscriptWatcher` (chokidar + lecture incrémentale, parser basé sur les fixtures du POC), rail d'agents à droite, clic → split console lecture seule (remplacement simple). Tests : parser sur fixtures, lecture incrémentale (offset).

4. **Plan V1-D — Notifications d'état.**
   Clignotement d'onglet + son configurable, pilotés par `Stop`/`Notification`/`SubagentStop` ; acquittement au re-clic. Tests : mapping événement→état→effet.

5. **Plan V1-E — Sidebar multi-projets + compteurs.**
   Liste des projets, compteur `sessions/agents` dérivé du Registry. Tests : agrégation des compteurs.

6. **Plan V1-F — Fermeture propre.**
   Modale si agents actifs, clean doux→SIGKILL avec délai de grâce, hook de fermeture (crochet pour le daily V1.5). Tests : séquence de clean, purge Registry.
